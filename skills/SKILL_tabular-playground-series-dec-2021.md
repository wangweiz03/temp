# Skill: tabular-playground-series-dec-2021

## 1. Task-Specific Reading
- This is a large synthetic tabular multiclass classification task. Predict integer `Cover_Type` for each test row from tabular feature columns derived from a Forest Cover Type-style source dataset.
- The evaluation metric is plain multiclass accuracy. The final decision is the predicted class, not probability quality. Probability models are still useful for CV, ensembling, class-prior handling, and argmax/postprocessing, but the metric rewards only correct hard labels.
- The data is synthetic, generated by CTGAN from a real tabular source. Expect many rows, mostly numeric or integer-coded features, possible one-hot-like indicator blocks, and relationships that may differ from the original source. Do not assume original-data relationships are fully valid unless the competition data confirms them.
- Treat `Id` as a row identifier only. It should not drive model splits or features unless an adversarial check proves row order has legitimate signal; default to excluding it from modeling.
- The target classes may be imbalanced, including potentially extremely rare classes. Accuracy makes majority and high-frequency classes dominate the objective, so class-weighting must be tested rather than assumed beneficial.
- Dominant score levers:
  - Strong, regularized GBDT multiclass models trained on all raw features plus a small set of robust count/interaction features.
  - Stable StratifiedKFold OOF probabilities with accuracy computed from `argmax`.
  - Ensembling across LightGBM, XGBoost, CatBoost, seeds, and moderately different capacity settings.
  - Detecting and handling rare/noisy classes through OOF confusion analysis and class-prior-aware postprocessing.
  - Avoiding leakage-prone target encodings and overfitted high-cardinality combinations unless they improve OOF accuracy consistently.

## 2. Highest-Expected-Score Strategy
- Converge toward a probability-level ensemble of diverse GBDT models, then convert to hard labels with accuracy-aware postprocessing.
- Use GBDTs as the core:
  - LightGBM multiclass GBDT as the fast workhorse. It should train on CPU and can handle very large row counts efficiently.
  - XGBoost `multi:softprob` with histogram trees as a high-value second family. Keep early stopping in the constructor and use a different bias/variance profile than LightGBM.
  - CatBoost multiclass as the third family when runtime permits. It can be strong on integer/categorical-like columns and often contributes useful ensemble diversity even when standalone CV is not best.
- Optimize for accuracy, but train with multiclass logloss-style objectives because they provide calibrated class probabilities for blending. Use OOF hard-label accuracy as the decisive metric, not only validation logloss.
- Use 5-fold StratifiedKFold as the default. With millions of rows, 5 folds gives stable estimates and enough validation rows for minority-class diagnostics. Use 3 folds only if multiple model families cannot finish under the time budget.
- Keep all folds identical across model families. Store OOF probability matrices for each model and average test probabilities fold-wise. Use these OOF matrices for all blend-weight and postprocessing decisions.
- Engineer features conservatively. This dataset is large and synthetic; raw GBDT splits on the original numeric and indicator columns should be very strong. Add only features that are unlikely to create distribution artifacts:
  - Row-level summaries over binary/indicator blocks, if such blocks are present.
  - Count/frequency encodings for integer-coded low/medium-cardinality columns using train+test values only, never target.
  - Pairwise arithmetic features only among the most important continuous columns discovered by an initial model.
  - Simple aggregate summaries such as row mean/std/min/max over related numeric blocks if feature names or distributions indicate coherent groups.
- For class imbalance, do not reflexively use heavy class weights. Accuracy often prefers modeling the common classes cleanly. Compare unweighted training against mild class weights or sample weights using OOF accuracy and per-class recall. If a class has vanishing train frequency and OOF never predicts it correctly, suppressing predictions for that class can improve accuracy.
- The strongest final route is:
  - Train several LightGBM variants: standard GBDT with different seeds, leaf counts, regularization, feature fractions, and perhaps one slower DART/GOSS-style variant if time permits.
  - Train one or more XGBoost variants with different depths and subsampling.
  - Train CatBoost variants on raw/integer features, marking low-cardinality integer columns as categorical only after testing.
  - Blend probabilities by OOF-optimized weights, then apply class-prior and confusion-derived postprocessing only when it improves OOF accuracy.
- Avoid prioritizing neural tabular models. A RankGauss MLP or denoising autoencoder can add diversity in late rounds, but for this task size and metric the expected ROI is lower than GBDT model/feature/ensemble work.

## 3. Strong First Implementation Plan
- Build the first complete solution around a serious 5-fold GBDT ensemble, not a single weak baseline.
- Preprocessing:
  - Drop `Cover_Type` from train features and drop `Id` from model features.
  - Preserve numeric/integer columns with minimal imputation. GBDTs can handle missing values; add missing indicators only for columns with visible missingness.
  - Downcast large numeric frames for memory, but do not alter feature meaning through aggressive scaling.
  - Identify binary/one-hot-like columns by unique values in `{0,1}` or low cardinality. Keep them as numeric for the first implementation.
  - Identify low-cardinality integer columns separately; they may be useful as categorical features for CatBoost/LightGBM variants later.
- First-round feature set:
  - Raw features.
  - For binary/indicator groups: per-row sum, count of zeros/ones, and if feature names reveal groups, group-wise sums.
  - For selected integer columns with low/medium cardinality: count encoding and normalized frequency encoding computed on the combined train+test feature column.
  - For top continuous features from an initial quick LightGBM, add a limited set of pairwise differences/ratios/products. Keep the set small, such as interactions among the top 8-12 continuous features, and retain only if OOF accuracy improves.
- Models:
  - LightGBM multiclass, `objective=multiclass`, `metric=multi_logloss`, moderate learning rate, many estimators with early stopping, `num_leaves` around 63-255, `min_data_in_leaf` high enough for millions of rows, column/row subsampling, L1/L2 regularization, CPU device.
  - XGBoost multiclass `multi:softprob`, histogram tree method, depth around 6-10, substantial `min_child_weight`, row/column subsampling, early stopping, and multiclass logloss evaluation.
  - CatBoost multiclass if time permits in round 1; use depth around 6-8, ordered boosting defaults where feasible, early stopping, and test whether treating low-cardinality integer columns as categoricals improves OOF accuracy.
- Training target and labels:
  - Map target classes to contiguous internal labels for model training, then map predictions back to the original `Cover_Type` values.
  - Train on all target classes present in the training data, but track class counts and per-class OOF recall.
- Validation:
  - Use StratifiedKFold on `Cover_Type`.
  - Compute fold accuracy from `argmax(probabilities)`.
  - Store OOF probabilities and test probabilities for each model/fold.
- Inference and postprocessing:
  - Average probabilities across folds for each model.
  - Start with an equal-weight blend of LightGBM and XGBoost; add CatBoost if its OOF blend improves accuracy.
  - Optimize blend weights on OOF probabilities with a small grid or coordinate search, maximizing hard-label accuracy.
  - After blending, apply only OOF-proven class suppression or class-threshold rules. For example, if a rare class is never correct in OOF, allow a rule that reassigns its predicted rows to the second-highest class and accept it only if OOF accuracy improves.

## 4. High-ROI Upgrades Across Rounds
- Round 2:
  - Tune LightGBM capacity and regularization first. Try deeper/high-leaf models with stronger `min_data_in_leaf` and regularization, plus shallower more regularized models for ensemble diversity.
  - Add XGBoost variants with different depths: one deeper model for interactions, one shallower model for smoother boundaries.
  - Test CatBoost with and without selected low-cardinality integer columns declared categorical. Keep whichever improves OOF blend accuracy, not just standalone score.
  - Expand count/frequency features for low-cardinality and medium-cardinality integer columns. Add pairwise count encodings for a small number of important categorical-like pairs only if OOF improves.
  - Perform class-prior and rare-class diagnostics. Tune class suppression or mild prior scaling on OOF probabilities when it improves hard accuracy.
- Round 3:
  - Build a larger probability ensemble using 2-4 LightGBM variants, 1-3 XGBoost variants, and 1-2 CatBoost variants. Use identical folds and OOF-optimized blend weights.
  - Try a LightGBM DART-style variant if time allows; it is slower but can produce useful probability diversity.
  - Add feature-selection-by-importance: train a quick LightGBM, drop consistently zero-importance engineered features, and avoid dragging noisy interaction features into every model.
  - Try a compact RankGauss MLP only as an ensemble diversity model. Use raw numeric/count features, cross-entropy loss, OOF probabilities, and include it only if the blend improves OOF accuracy.
  - Explore OOF confusion-matrix rules: if two classes are systematically confused, test small per-class probability multipliers or thresholds rather than arbitrary manual relabeling.
- Late round:
  - Use hill-climbing or coordinate descent over OOF predictions to choose blend weights and model inclusion. Optimize hard accuracy directly.
  - Train final selected models with multiple seeds when single-seed variance is visible in OOF.
  - Consider level-2 stacking using only OOF probability columns, with a very regularized multinomial logistic regression or ridge-style meta-model. Accept stacking only if it beats simple weighted blending under the same folds.
  - Consider pseudo-labeling only if blended test probabilities show a large set of very high-confidence rows and OOF experiments with pseudo-labeled validation analogs look stable. For plain accuracy on synthetic data, pseudo-labeling can overfit public distribution artifacts, so it is late-round only.
  - Revisit feature engineering from feature importance and SHAP-style diagnostics only for targeted interaction additions. Broad brute-force feature generation is lower ROI once the ensemble is mature.

## 5. Validation and Metric Optimization
- Use StratifiedKFold as the primary validation because the target is multiclass and potentially imbalanced. The split must preserve class ratios so rare-class decisions can be judged.
- If a class has too few examples to support 5 folds, reduce folds or use repeated stratified splits that keep every class represented. Do not allow a fold where a target class is absent from validation if rare-class postprocessing is being tuned.
- Trust OOF accuracy from identical folds over individual public leaderboard movement. This is a large synthetic dataset; small leaderboard differences can come from distribution quirks, while OOF gives a fuller view of class-wise behavior.
- Track three OOF metrics:
  - Overall accuracy from hard `argmax`.
  - Multiclass logloss for probability sanity and blend smoothness.
  - Per-class recall/support and confusion matrix for rare-class and class-pair decisions.
- Optimize blends on OOF probabilities by hard accuracy. Logloss-improving blends may not improve accuracy if they only recalibrate already-correct predictions.
- Use probability averaging, not majority vote, as the default ensemble method. Probability averaging allows weighted blends, rare-class suppression, and class-prior scaling.
- Tune postprocessing with strict OOF discipline:
  - Class multipliers: multiply each class probability by a small scalar, then argmax; search near 1.0 and keep only OOF gains.
  - Rare-class suppression: if OOF predictions for a class have extremely low precision and support is tiny, test reassigning those predictions to the next-best class.
  - Threshold rules: use only for classes with strong OOF precision/recall tradeoffs; avoid complex row-wise rules that will not generalize.
- Do not target logloss as the final objective. Use it to train and blend, but final model selection should be based on OOF accuracy after all postprocessing.

## 6. Model, Feature, and Preprocessing Priorities
- Highest-priority models:
  - LightGBM multiclass CPU GBDT with tuned `num_leaves`, `min_data_in_leaf`, feature fraction, bagging, and L1/L2 regularization.
  - XGBoost multiclass histogram models with different depths and `min_child_weight` for diversity.
  - CatBoost multiclass, especially if low-cardinality integer/categorical-like columns exist.
- Highest-priority features:
  - All raw numeric and indicator features.
  - Count/frequency encodings for discrete columns and selected discrete interactions.
  - Row-wise summaries over binary/indicator blocks.
  - Target-independent group summaries only when feature names or cardinalities indicate real groups.
  - Limited arithmetic interactions among the most important continuous features.
- Highest-priority preprocessing:
  - Preserve missingness for tree models; add indicators only when missingness exists and is nontrivial.
  - Treat low-cardinality columns as candidate categoricals for CatBoost and LightGBM variants, not blindly for every model.
  - Keep feature generation train/test distribution-safe. Count encodings can use train+test feature values; target encodings must be OOF-only and are not a first-round necessity.
  - Map labels cleanly to contiguous internal classes and back to original class labels for output.
- Highest-priority diagnostics:
  - Feature importance stability across folds.
  - OOF confusion matrix by class.
  - Prediction distribution versus training class distribution.
  - Per-model OOF correlation; add models that are both strong and diverse.

## 7. Avoid or Delay
- Avoid any image, text, audio, sequence, or deep computer-vision transfer. This is pure tabular classification.
- Avoid external datasets or original source data as the default plan. The task description says the synthetic relationships may differ from the real source, and external data availability is not guaranteed.
- Avoid using `Id` as a default feature or creating row-order leakage features without clear adversarial evidence.
- Avoid global target encoding, target encoding computed before CV splitting, or interaction target encodings without OOF construction.
- Avoid optimizing only multiclass logloss. The leaderboard metric is hard-label accuracy; always validate the final `argmax` behavior.
- Avoid aggressive class weights as a default. Heavy reweighting can improve rare-class recall while lowering total accuracy.
- Avoid forcing predictions for extremely rare classes. Let OOF precision/recall decide whether a rare class should ever be predicted.
- Avoid broad polynomial or pairwise arithmetic explosions in the first round. On millions of rows, noisy features increase runtime and can hurt GBDT split quality.
- Avoid complex neural tabular models before a strong GBDT ensemble exists. Use NNs late only for diversity and only with OOF evidence.
- Avoid stacking until clean OOF predictions from several strong base models exist. Weighted probability blending is usually the safer first ensemble.
- Avoid trusting a single fold, single seed, or public leaderboard jump for postprocessing rules. Class threshold and suppression rules must survive full OOF evaluation.
